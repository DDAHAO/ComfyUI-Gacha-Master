# 日常操作与异常处理

本文件只描述用户界面需要完成的操作；诊断细节与证据路径放在报告/日志中。适用于 Windows 11、本地单用户、ComfyUI 0.45.0 的已验收隔离组合；目标生产实例仍需按 [REAL-ACCEPTANCE-RUNBOOK.md](REAL-ACCEPTANCE-RUNBOOK.md) 验收。

## 1. 创建任务：CREATING 与“开始”的区别

1. 打开图生图工作流，确认包含标准 `LoadImage`、最终 `SaveImage`，采样器种子是直接数值。
2. 侧栏“新建任务” → 捕获工作流 → 绑定输入/最终输出 → 添加原图 → 设置每图次数 → 检查并创建。
3. 创建只登记任务并分批生成 DRAW/种子，状态为 **CREATING**；完成后变为 **READY**。此阶段**不会推理**。
4. 必须显式点击“开始 / 继续”才会提交推理。关闭浏览器、重连、重启都不会自动开始。
5. 创建中可“暂停创建”“放弃创建”；继续创建不会自动启动推理。

## 2. 运行、暂停与浏览器关闭

- “安全暂停”等待当前 DRAW 结束并核验后进入 PAUSED；“立即暂停”在未验证定向取消的实例上会降级为等待当前项结束。
- 关闭浏览器不影响已授权任务；重新打开侧栏会同步真实进度。
- 任务列表/详情显示的是服务端权威状态，不以动画或本地乐观值为准。

## 3. 分页、后页筛选与入选

- 原图按稳定 `source_order` 分 40 行/页；结果按 50 张/页，单源最多缓存 3 页。用“首页/上一页/下一页/定位”移动；定位按原图编号，不把全部原图载入内存。
- 后页入选会立即保存到服务端；离开详情、刷新、切换对照后星标应保持。
- 两个标签同时修改同一 OUT 时，旧版本请求返回 **409**：界面恢复原值并回读权威状态，不会自动补写旧意图。看到“已在其他页面变化”时，以刷新后的星标为准。
- 空格/Enter/右键可切换入选；键盘焦点应留在卡片的星标上。

## 4. 对照与导出

- 点击缩略图进入对照；默认并排，可切换“滑动对比”。原图与结果比例不同会提示返回并排，不裁切/拉伸。
- 导出类型：QUICK（当前健康入选）/ FINAL（逐原图审核）；布局：FLAT/GROUPED。
- 正式导出必须逐原图“确认入选”或“明确跳过”；存在未完成 DRAW 时要确认“只导出当前截止版本”。
- 导出复制按冻结成员执行，不移动/重编码/覆盖源结果。部分失败会显示失败项，可“继续复制”；已成功文件不重复复制。
- 预览过期（409）时点“刷新预览”，重新审核后再冻结。

## 5. 网络中断、慢响应与恢复

- 断网/服务停止：侧栏显示“同步中断”和最后成功同步时间；已有页面保留，后台任务不受影响。
- 恢复后客户端重新读取任务/原图/结果；不会自动补写旧操作，也不会自动开始推理。
- 缩略图失败不会用空块或别的图片冒充结果；可刷新重读。

## 6. 服务重启与 UNKNOWN

- 重启后先核验本地收据、结果文件与远端 history/queue；不会自动重提。
- 状态为 **RECOVERY_REQUIRED / UNKNOWN** 时，打开恢复面板逐项处理：
  - 远端确认已成功：确认完成，不新建 ATTEMPT；
  - 确认未提交/未执行：按同种子人工重试，新增 ATTEMPT；
  - 无法确认：保持 UNKNOWN，不要猜测成功。
- 绝不自动重 POST UNKNOWN；同一 DRAW 最多一个接受 OUT。

## 7. 导出部分失败与文件冲突

- 导出一项失败不会回滚已复制文件；修复源文件/目标目录后“继续复制”。
- 目标文件已存在且不是同一内容时拒绝覆盖；不要手工改名冒充成功。
- 导出 manifest、DB 与目标文件三者必须一致；报告会列出失败项。

## 8. 磁盘不足与恢复

- 插件按卷检查保留空间；reserve 不足、结果根只读、结果卷失联会在提交前阻断并保留现场。
- **真实磁盘写满（ENOSPC）尚未验收**（2026-11-15：无受控卷）。工具侧的写入保护与阶段同步协议已完成，但“真实业务写入撞到 ENOSPC 并恢复”仍是 NOT_RUN；不要据此认为磁盘故障路径已被证明。
- 出现写失败时：
  1. 停止创建/开始新任务，不要反复重试；
  2. 保留错误码、日志、DB 与结果目录；
  3. 释放空间后先做一次备份/完整性核验，再显式恢复；
  4. 不要手工删除已接受 OUT/导出成员；不要删除 `pre-restore-*` 或 `install-backups`。
- 未确认的写失败保持保守状态（UNKNOWN/阻断），不要以文件存在或 HTTP 200 单独判定成功。
- 运维/验收侧做写满测试时只能用**明确归本轮、可丢弃**的 NTFS 卷，并按 [REAL-ACCEPTANCE-RUNBOOK.md](REAL-ACCEPTANCE-RUNBOOK.md) 第 10 节执行；系统卷、项目卷一律拒绝，工具在写入入口自行复核。

## 9. 备份、升级与回退

- 在线备份位于 `data_root/backups`；备份恢复会先保留 `pre-restore-*.sqlite3`。
- 代码升级：用 `tools/install_plugin.py --mode copy --update`；旧代码备份在 `user/gacha_master/install-backups`，不在 `custom_nodes` 内，避免被当成第二个插件加载。
- 回退代码前先停服；只切回旧代码**不等于**数据库可回退：
  - 旧代码不支持新 schema 时会拒绝启动/写入，这是保护，不要绕过；
  - 数据库回退必须使用升级前一致性备份，并保留升级后库/结果作为证据；
  - 恢复后重新核对任务、选择、冻结导出、接受关系与文件哈希。
- 卸载默认保留任务数据、结果、导出与备份；清理是独立操作，见 README。

## 10. 定向取消

仓库默认 `targeted_cancel_verified=false`。目标实例需要立即取消时，先按 [REAL-ACCEPTANCE-RUNBOOK.md](REAL-ACCEPTANCE-RUNBOOK.md) 在隔离/目标实例验证运行中与排队中取消及外部哨兵任务；通过后才显式开启。只用安全暂停不阻塞使用，但报告必须标注降级能力。

## 9. 清理未入选结果与缩略图缓存（2026-11-17）

### 9.1 什么时候可以清理

1. 任务必须已完成（状态 **COMPLETED**、运行意图 **已停止**），且没有 PENDING/在途/UNKNOWN/RECONCILING 执行。
2. 每个有结果的原图组都必须按当前“结果版本 + 选择版本 + 计划版本”完成组确认（保留或跳过）。只浏览过、只看过最后一张、筛选会话结束都不算确认。
3. 仍有未确认组时，预览返回 `CLEANUP_NOT_ELIGIBLE` 并提示“继续筛选”，不会删除任何图片。
4. 正在冻结/复制/待恢复的导出会阻止清理；历史导出、有效导出草稿引用的结果始终受保护。

### 9.2 操作步骤

1. 打开“任务详情 → 存储清理”，确认“当前留存/已入选/已清理”统计。
2. 点击“清理未入选结果”。服务器只生成预览：
   - 候选张数与预计文件字节；
   - 入选保护数、导出引用保护数、其他排除原因；
   - 候选缩略图与原图/抽次/OUT 编号。
3. 关闭预览或点“取消”不会删除任何文件。
4. 点击“永久清理 X 张结果”，再在二次确认框点“永久删除”。只缺一步都不会执行。
5. 清理在后台执行；关闭页面不会取消。重新打开任务详情可看到同一记录与实时成功/失败/跳过进度。
6. 完成后页面会刷新统计、分页、筛选断点和存储占用。部分失败会显示成功/失败数量与失败原因；失败文件保留且可读，成功项不会回滚。

### 9.3 必须知道

- **删除不可撤销**。数据库备份只保存记录，不包含图片；恢复旧备份不能找回图片。
- 原图、原图快照、入选图片、导出成品、清单/收据、工作流、种子、DB、备份与日志都不会被本功能删除。
- 已清理结果不会显示为“可用”，也不会被再次入选或导出；历史模式（勾选“包含异常输出”）可看到“已清理”标记。
- 再次清理只能处理新产生的未入选结果或上次失败项；必须重新预览，不能沿用旧确认。
- 若恢复清理前的旧数据库，服务启动会从清理日志重建“已清理”事实；旧备份中指向已清理图片的“入选”会显示为失效，导出会被阻止，请取消该失效入选后再导出。
- 浏览器可能仍缓存已看过的图片副本；服务端清理不会立即清除浏览器缓存。

### 9.4 缩略图缓存

“设置与存储 → 存储占用 → 清理可重建缩略图缓存”只删除受控的缩略图 JPG：

- 会报告扫描、删除、失败、跳过数量与字节；被占用/只读文件的失败可见，不再静默忽略。
- 不删除完整结果、原图、清单、数据库或备份；再次浏览会重新生成，缓存占用可能增加。
- 结果图片和缩略图是互斥分项；“结果目录合计”已经包含缩略图，不能重复相加。
- 任务级清理可能顺带删除已无其他留存 OUT 引用的输出缩略图；共享内容哈希仍被引用时保留。

### 9.5 迁移与备份

- 迁移数据根时，除 SQLite/原图/结果外，必须一起保留 `storage-identity.json` 和 `jobs/<job>/cleanup/`，否则无法区分“有意清理”和“意外缺图”。
- 数据库备份/恢复不包含图片，也不能撤销已完成的删除；恢复后所有旧预览失效，需要重新预览确认。
- 清理日志写满/只读/DB 只读或进程强退时，重启会先对账：未闭合的删除意图若文件仍在，会关闭为取消并保留文件；若文件已不在，才补记已清理。状态不明时显示“需要核清”，不会当作全部成功。
